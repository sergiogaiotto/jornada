## Detalhe dos use cases

### UC01 · Consultor com IA real na Sala de Ideação
**Passos:** OS demo → Briefing · Ideação → pergunta consultiva na conversa ("vale a pena estender para controle ARPU>60? o que recomenda?") → analisar prévia → Rejeitar.
**Observado:** 120B respondeu em ~10s; prévia mostrou o campo `publico` com valor atual vs inferido, premissas, botões Aplicar/Rejeitar, selo "IA copilota · humano aprova". Rejeitar removeu a prévia sem tocar o briefing. ✅
**Achados:** A1 (extração por frase corrida = 80%; com rótulos = 100% — sensível à forma). A2 (**médio**): em OS com briefing 14/14, o agente respondeu "falta objetivo, oferta, verba e janela" — contradição visível — e não exerceu papel consultivo (só extrai). *Corrigido no lote (contexto de OS completa).* 

### UC02 · Criar campanha pela UI — lacuna
**Observado:** nenhum botão "novo/criar/pedido" em tela alguma; paleta ⌘K é só navegação. O digest do Cockpit instrui "crie um pedido na Sala de Ideação", mas a Sala é por-OS (só existe após a OS existir). Fluxo de entrada só via API/portal. **A3 (alto, produto):** falta a porta de entrada do solicitante na UI. *Pendência de produto (não corrigida no lote).* 

### UC03 · Cockpit
**Observado:** KPI row (no ar/aguardando/em risco/no ciclo), kanban por fase, card com t-shirt+fase+saúde "Normal" derivada; seleção habilita todo o menu; painel contextual traz fase, saúde ("nunca editável" ✓), últimas ações com badge via_ai clicável e "Abrir OS →". ✅
**Observação A4:** clique via automação (coordenadas) não selecionou o card; clique DOM real funciona — investigar área clicável/hit-target (não reproduzido manualmente; baixa prioridade).

### UC04 · Validação campo-a-campo + pendência
**Observado (1ª rodada):** "Validar" → **"Erro interno inesperado"** — **A5 (crítico):** a imagem docker da API não continha `mocks/seeds/*.json` usados em runtime (validação e recontagem). *Corrigido e deployado no ato (`fix(docker)`).* 
**Observado (2ª rodada):** validação com evidência "✓ contagem · ✓ schema · ✓ frescor" ✓ e Pendência #1 aberta — mas a aba de rede revelou **A10 (alto):** todos os botões Validar/Abrir pendência POSTam para `/validacoes/objetivo` independentemente do campo (bug de binding no map do React). GO permaneceu bloqueado "1 de 5". *Corrigido no lote.* **A9 (UX, baixo):** pendência nasce com 1 clique, sem diálogo de título/descrição.

### UC05 · Esteira ex-Hike + Criativo
**Observado:** 7 etapas na ordem, Criativos com checklist (4) e Acompanhamento (D+1/D+7/D+15) ✓; Iniciar etapa 1 → "em andamento" ✓; Iniciar etapa 3 com dependência insatisfeita → **backend segurou** (ficou pendente) mas **A6 (UX, médio):** o 409 é silencioso — sem banner explicando o bloqueio. *Corrigido no lote.* No Criativo: **A8 (médio):** KV master default hardcoded da campanha de franquia aparece em OS de recarga (não deriva do briefing). *Pendência.* 

### UC06 · Audiência + Guard
**Observado:** "Gerar SQL (Engineer)" → recusa clara na UI: "Não disponho das evidências RAG (dicionário de dados)… não é possível gerar o SQL conforme compliance". Guard-rail `exige_evidencia` correto (não inventa SQL de segmentação!), erro bem exibido. **A11 (alto, infra):** a base RAG (pgvector + ingestão do dicionário) **não está provisionada em produção** — Engineer inoperante na VPS até provisionar. *Pendência de infraestrutura.* 

### UC07 · Data Cloud
**Observado:** catálogo com 4 segmentos (membros, "republicado há 6h · ciclo diario", status incl. "republicando"); relatório completo: 1.240.580 → elegível 1.180.200 (−7 listas) → líquido 826.580; sobreposição nomeada (121k DC-SEG-002); frescor por fonte (data cloud 6h · hybris 24h · governor 2h); volume de abordagem por canal (E-mail 603,6k·73% … WhatsApp 252k·30,5%) com colisões do governor e mix recomendado. ✅ forte.
**A12 (médio):** não há botão "Usar como entrada no Estúdio" — a ação existe na API, não na UI. *Corrigido no lote.*

### UC08 · Twin (gerar com Flow real)
**Observado:** "Gerar jornada (Flow)" → **500**. Traceback: `KeyError: 'to'` no taxímetro — o 120B emitiu edges `source/target`; o `jgc_validate` não pegou (gap estrutural — se pegasse, o retry §7.3 corrigiria via reprompt) e o taxímetro quebrou. **A13 (alto).** *Corrigido no lote (normalização de aliases + validador de edges + taxímetro defensivo).* 
**A14 (alto p/ demo):** OS demo em fase monitorada abre o canvas "Sem versão do twin" — sem GET de leitura de jornada e sem grafo nas seeds. *Corrigido no lote (novo GET §8-M7 emendado no SDD + grafo na seed).* 
**A15 (médio):** ids das seeds são uuid4 a cada restart → links/bookmarks quebram silenciosamente (o front mostra cache e depois 404). *Corrigido no lote (uuid5 determinístico).* 

### UC09 · Ensaio/portões
**Observado:** rota `simulacao` da OS sem twin → **página 100% branca**; console: `React error #185` (maximum update depth). **A16 (crítico de robustez):** loop de setState + ausência de Error Boundary global — qualquer erro JS apaga o app. *Corrigido no lote (guard no efeito + ErrorBoundary com fallback).* Link mágico/pré-voo/rampa não puderam ser exercitados pela UI nesta rodada (dependiam do twin da OS de teste); cobertos pelo e2e HTTP do MS8.

### UC10 · Monitor + Pergunte aos Dados + Ateliê + Langfuse
**Observado (Monitor):** "Monitoramento Dinâmico ● Dinâmico · onda 2/3"; snapshot hash; conversões 271 (prev. 248 · +9,3%), lift +24,1pp (prev +21 · IC95 18,6–29,6 · significativo), ROAS 18,5x (prev 15,2x), custo real vs P50 congelado. ✅
**Observado (Perguntas):** pergunta de PII entre as sugestões ("CPF…") → recusa padrão "nenhuma consulta foi executada" ✓; pergunta válida via chip → consulta nomeada `roas` + JSON previsto P10/P50/P90 vs realizado + via_ai ✓. **A17 (médio):** "qual canal deu mais conversão por real gasto?" (legítima → custo_por_pedido) foi recusada — classificador recusa demais. *Corrigido no lote (mapeamento de sinônimos).* 
**Observado (Ateliê):** roster por etapa com filtros ✓; **A18 (baixo):** "0 triagens" (roster §7.2 previa 5) e harness "— sem run" em produção. *Pendência.* 
**Observado (Langfuse):** 7 traces da própria sessão (consultor.mensagem ×4+, insight.perguntar ×2) no projeto jornada-demo. ✅

### Achados novos desta rodada

**A24 (alto) · Evidência de compliance dependia de sorte semântica.** Com o RAG operante, o Engineer mudou de "não disponho de evidências" para uma recusa **específica** (faltavam opt-in por canal e `lista_supressao`) — embora as entradas existissem na base. Causa: retriever puramente semântico (top-k=8) e a consulta "pós-pago 5G com ARPU alto" trazia só colunas de plano. **Correção:** evidências marcadas com `meta.sempre_incluir` entram sempre, à frente do top-k (dedup por id) — as 7 listas, os 4 opt-in e a chave de ativação. *Princípio: o que o Guard sempre exige não pode depender de ranking.* Resultado na VPS: SQL com `NOT EXISTS` das 7 listas e opt-in por canal no `WHERE`.

**A25 (médio, arquitetural) · Import com efeito colateral.** `app/main.py` criava o app no nível de módulo (`app = create_app()` para o uvicorn). Com `DATABASE_URL` setado, **importar** o módulo já semeava roster/políticas — e no CI de integração as migrações ainda não tinham rodado, quebrando a **coleta** dos testes (`relation "agente" does not exist`). **Correção:** app de módulo removido; todos os runners usam a factory (`uvicorn app.main:create_app --factory`). Import voltou a ser puro.

**Observações menores registradas:** o pull único da imagem `pgvector:pg16` (640 MB) fez a suíte parecer travada (66 min na 1ª execução, 20 s depois) — não era bug; o job `deploy` não faz checkout, então o SHA passou a ser calculado por substring (`${GITHUB_SHA:0:7}`), com corte fixo de 7 nos dois lados para imunizar contra `core.abbrev`.
